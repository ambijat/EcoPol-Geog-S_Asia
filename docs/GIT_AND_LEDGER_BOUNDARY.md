# Git and Academic Ledger Boundary

Git and the course ledger serve different purposes.

| System | Purpose | Typical events |
|---|---|---|
| Git | Technical file history and reproducibility | templates, scripts, formatting, corrections, tests, reports, directory structure |
| Course ledger | Academically consequential chronology | weekly lecture pair approved, Tuesday or Friday class conducted, major reading added or removed, substantive topic deferred, assessment blueprint approved, retrospective approved |

Routine file changes do not require ledger blocks. A Git commit does not imply academic approval, and a valid ledger hash does not prove that a claim is true. Existing ledger blocks are append-only and must never be edited manually. Codex may not mark a block `APPROVED` or `SEALED` without explicit instructor authorisation.

Website publication is neither Git history nor the authoritative archive. Only instructor-approved project artifacts may be published, and the project retains the authoritative reviewed version and provenance record.

Directory creation, placeholder files, deck formatting, filename changes, PDF export, validation runs, and other routine production mechanics do not receive ledger blocks. Codex may prepare a draft event for an academically consequential milestone but cannot approve, append as approved, or seal it without explicit instructor authorisation.
